# v0.51.0-arana.1 审计问题修复设计

## 目标

在不改写既有 `v0.51.0-arana.1` 标签、不执行远端 GitHub 写操作的前提下，修复标签审计发现的可在源码侧闭环的问题，并让 Kiwi 的依赖固定到该标签解引用后的精确 commit `971c792f3d6312204a5e162bd60d4d3c84a9e8a8`。

## 范围

### rust-rocksdb

1. 纠正 readable properties 的验收语义。验证性变异已经证明真实 flush 会执行 Rust callback，并穿过 C ABI/C++ adapter；进一步的 SST readback 失败是 RocksDB 的预期行为，因为 readable properties 只用于构建期日志、不写入 property block。当前 Rust EventListener API 也未暴露底层 flush table properties，因此本轮不新增错误的持久化语义或额外公开 API，只在 Release/API 文档中明确边界。
2. 将子进程 watchdog 的 poll、terminate、wait 行为抽象成可故障注入的小单元。所有非正常分支必须先尝试终止并回收 child；kill 失败后复查 child 状态，已经退出时正常收集输出，仍在运行或复查失败时将 child 移交给预启动的固定 reaper 并立即返回，不进入无界 `wait_with_output()`。
3. 将 GitHub Actions 中无效的 `save-if` 全部改为 `cache-save-if`。
4. 补充 `v0.51.0-arana.1` release notes、CHANGELOG 封板信息和 Arana 仓库来源说明。Cargo crate 版本保持 `0.51.0`，因为本轮不发布 crates.io 包，也不修改已经存在的 tag 内容。

### Kiwi

Kiwi PR #364 已完成 API 适配和兼容性验证，PR #366 已把 `Cargo.toml` 固定到 `v0.51.0-arana.1`，且 `Cargo.lock` 已解析到最终标签 commit `971c792f...`。本轮只修正历史升级计划中仍把 `dd1ac21a...` 描述为当前 pin 的过期文字，不修改依赖清单、锁文件、property key/value、恢复算法或公共接口。

## 不在范围内

- 不 force-retag 或删除既有 tag。
- 不创建 GitHub Release、push、merge 或创建 PR。
- 不修改 `LargestLogIndex/LargestSequenceNumber` 与 `<log_index>/<sequence_number>` 编码。
- 不把 system RocksDB backend 改造成支持 Collector Factory；它继续 capability=0、fail-closed。

## 验证

- 每个行为修复先运行新增测试并确认 RED，再实现到 GREEN。readable 项保留变异证据：固定空 native callback 时真实 flush 测试可证明 Rust callback 未被执行；恢复后 callback 执行，但 SST readable map 为空，符合 RocksDB 文档语义。
- rust-rocksdb 至少执行格式检查、Collector/Factory 23+ 项测试、TableProperties read、EventListener，以及 workflow 静态扫描。
- Kiwi 执行锁定依赖解析、格式检查、锁文件精确 SHA 扫描和文档 Diff 检查；由于本轮 Kiwi 只有历史计划文档变化，代码测试沿用 PR #364/#366 在精确主线 Head 上的既有验证，不重复触发原生全仓构建。
