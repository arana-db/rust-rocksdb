Kiwi. It retains crate versions `rust-rocksdb 0.51.0` and
`rust-librocksdb-sys 0.47.1+11.1.2`; it is a Git dependency baseline, not a

## TableProperties Collector and Factory

This baseline adds safe Rust `TablePropertiesCollector` and
`TablePropertiesCollectorFactory` interfaces over additive Arana C ABI and C++
adapters. The contract is designed for RocksDB's concurrent factory use:

- `TablePropertiesCollectorFactory` is `Send + Sync + 'static` and creates a
  per-SST collector with `create(&self, context)`. Implementations written for
  the previous `create(&mut self)` prototype must change the receiver to
  `&self` and put shared mutable state behind an appropriate synchronization
  primitive when it is genuinely needed.
- Collector user properties are byte-oriented end to end. Keys and values may
  contain NUL bytes, non-UTF-8 bytes, or empty values without C-string
  truncation.
- Rust panics are contained at collector, factory, and destructor FFI
  boundaries. Native pointer/length inputs are validated and ownership is
  transferred or destroyed exactly once.
- The bundled backend advertises the Arana collector-factory capability. A
  system RocksDB build reports capability `0`, and the safe registration API
  fails closed rather than relying on extension symbols that the system
  library may not provide.

### Readable properties are not persistent metadata

`TablePropertiesCollector::get_readable_properties` feeds RocksDB's SST
construction-time logging and diagnostics. RocksDB does not add that map to the
persisted table property block. An SST property lookup or a database reopen can
therefore expose an empty `readable_properties()` map even when the callback ran
and returned entries; this is expected upstream behavior.

A real mutation probe forced the native readable callback to return an empty
map and demonstrated that a real flush detects the missing Rust callback. After
restoring the adapter, the callback executed through Rust -> C ABI -> C++, while
SST readback remained empty as specified above. Durable recovery metadata must
instead be returned by `finish` as user-collected properties. This release does
not add a public event API for observing the transient construction-time map.

## EventListener migration

The EventListener bridge now applies fixed panic handling and ownership rules
to listener callbacks and destruction. Registration requires a `'static`
listener. The source-level migration required by this baseline is:

```rust
fn on_background_error(
    &self,
    reason: DBBackgroundErrorReason,
    status: &MutableStatus,
) {
    // inspect or update status during this callback
}
```

The previous signature took `MutableStatus` by value. Implementations must now
accept `&MutableStatus`; the wrapper must not retain that reference after the
callback returns.

## Kiwi integration

Kiwi merged the source adaptation in
[`arana-db/kiwi#364`](https://github.com/arana-db/kiwi/pull/364) and then moved
the dependency to the maintenance tag in
[`arana-db/kiwi#366`](https://github.com/arana-db/kiwi/pull/366). Kiwi's
`Cargo.toml` uses `tag = "v0.51.0-arana.1"`, and its `Cargo.lock` resolves both
fork crates to target commit
`971c792f3d6312204a5e162bd60d4d3c84a9e8a8`. The LogIndex recovery property
continues to use the user-collected
`LargestLogIndex/LargestSequenceNumber=<log-index>/<sequence-number>` format.

## Fixes after the tag

The following fixes are present only in the post-tag working branch. They are
not part of tag object `4a9d2fec47ec467b00a9701f9db14eaffeca806a` or target
commit `971c792f3d6312204a5e162bd60d4d3c84a9e8a8`. Because that tag is immutable,
these fixes can only enter a subsequent maintenance tag and release. If a
GitHub Release object is later created for `v0.51.0-arana.1`, they can only be
listed there as known post-tag fixes, not as content of the existing tag:

- make the asynchronous callback-panic watchdog surface poll and wait errors,
  and hand a still-running child to a fixed worker/reaper when kill fails
  instead of synchronously waiting without a bound;
- replace five unsupported Rust cache `save-if` inputs with `cache-save-if`;
- correct the root crate homepage/repository and the sys crate repository to
  `https://github.com/arana-db/rust-rocksdb`. The immutable tag itself still
  contains the previous repository metadata.
